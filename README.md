# QQ Role Cards

角色卡仓库。每张卡是一个可导入后台的独立角色包：人设、行为、好感度、运行配置、形象素材，语音后续接入。

这个仓库只管“角色卡是什么”，不直接跑 QQ 机器人。后台导入后，才把卡变成可用的角色。

## 快速配置

把沈幼楚挂到现有 `qq-bridge`：看 [`docs/quickstart.md`](docs/quickstart.md)。  
只要卡本体和配置说明，直接 clone 这个仓库；要整套 QQ 运行时，去 [`qqbot-dsh-stack`](https://github.com/dabao9037/qqbot-dsh-stack)。

## 一张卡包含什么

```text
cards/<id>/
  card.json        # 卡的身份、好感度、节奏、身份分支、素材索引
  persona.md       # 人设正文：她是谁、怎么说话、边界
  behavior.md      # 这张卡自己的行为预设（不替代全局工具协议）
  examples.md      # 对话样例：只学语气/节奏，不照抄
  assets/          # 角色形象图；用户后续生成
  voice/           # 语音素材/音色引用；先留空
```

`card.json` 里的运行配置是**卡自带的默认值**。导入后运行时只读，后台不提供手调主动间隔、表情概率、好感阈值这些入口；普通自设模式仍然走原来的后台配置，两套系统互不覆盖。

## 沈幼楚 · 当前默认值

好感度 0–100，初始 20，隐藏，不显示数值。每个“角色卡 × QQ”一份，A 和 B 不共享；身份线不改变好感度，只改变剧情关系。

| 阶段 | 区间 | 解锁 |
|---|---:|---|
| 陌生 | 0–19 | 只文字 |
| 眼熟 | 20–44 | 只文字 |
| 说上话 | 45–69 | 表情包 |
| 亲近 | 70–89 | 语音 |
| 交心 | 90–100 | 照片 |

- 每轮有效聊天基础 +0.2，单日最多 +5。
- 用户主动说自己的事 +2；帮忙、记住细节、守约 +2；关键共同事件 +3。
- 冲突 -5；越界 -10；单次事件限制在 -10 ~ +5。
- 3 天没有互动后，每天 -1，最低 0。
- 后台不能改数值，只能重置某个 QQ；重置会把这条线的记忆、好感、剧情、关系、背景状态全部清掉，回到初始 20。
- 解锁只是“允许”，不是“必须发”；角色仍可按语境和情绪拒绝。

### 回复概率

| 好感度 | 回复概率 |
|---:|---:|
| 0 | 1% |
| 1–4 | 5% |
| 5–9 | 5% 到 25% 线性 |
| 10–19 | 30% |
| 20 以上 | 100% |

### 主动消息

低于 40 不主动。到 40 后按区间随机：

| 好感度 | 主动间隔 |
|---:|---|
| 40–49 | 24–30 小时 |
| 50–59 | 16–20 小时 |
| 60–69 | 10–14 小时 |
| 70–79 | 6–9 小时 |
| 80–89 | 4–6 小时 |
| 90–94 | 3–4 小时 |
| 95–100 | 2–3 小时 |

主动消息还有三条硬限制：用户 30 分钟内说过话不发；上一条主动消息没回不叠下一条；00:00–07:00 不发。

详细规则见 [docs/affection.md](docs/affection.md)。

## 对话语境：先判断这句冲谁

关键词不能直接等于“在骂角色”。运行时先判这一轮的对话行为，再决定角色怎么反应：

- **直接骂角色**：如“你傻逼吧”“我是你爹”。低好感会扣分并回一句；提示词要求先针对他骂的那句顶回去，不转移话题。
- **倾诉/吐槽第三方**：如“今天被领导骂了，真傻逼”“领导骂我，真傻逼”“傻逼领导”。不扣好感，也不还嘴；先接住“谁骂了他/发生了什么”。
- **自嘲/转述**：如“我真傻逼”“我朋友说你傻逼”。不按攻击角色处理，先接对方的话。
- **道歉/找补**：如“对不起，我喝多了”“号被盗了”。刚吵完或低好感时优先回这一句；提示词要求先接道歉，不要先纠正名字、翻旧账或拿“我去忙了”岔开。
- **随机回复挡掉的连续消息**：下一轮会把这些没回的消息一起放进提示词，要求“先回最需要回应的，不要只答最后一句”。

借鉴的结构（只借机制，不照搬台词）：

- [CharacterGLM](https://github.com/thu-coai/CharacterGLM-6B)：把角色的“属性”和“当下行为”分开；先判对话行为，再按角色性格反应。
- [Ditto](https://github.com/OFA-Sys/Ditto)：角色身份一致性与知识边界；被骂也不突然变成通用客服或跳出角色解释。
- [RoleLLM](https://github.com/InteractiveNLP-Team/RoleLLM-public)：role profile → prompt → response 的结构，提示词只给约束，不写死台词。
- [SillyTavern](https://github.com/SillyTavern/SillyTavern)：World Info 按当前对话激活、动态提示放在生成位置附近；本项目的 `selectLore` / `threadPrompt` 沿用这个思路。

## 独立记忆

角色卡模式有自己的一条记忆，不读普通人格的记忆，也不把普通会话的历史带进来：

- 每条「卡 × QQ」一份：`state/role-cards/<cardId>/<qq>/memory.json`。
- 记五类东西：对方明确说过的长期事实、你们之间发生过的片段、后台生活日记、后台反思、还没说完的事。
- 事实带种类和有效期：住处/工作这类单值事实被新说法替代时，旧事实标记失效但不删除；喜好可以并存。
- 每次注入不是“最后几条”，而是按 **当前记忆强度 + 相关度 + 重要度** 选一小撮；当前话题相关的会排在前面，不把整份聊天记录倒给模型。
- 记忆会像人一样褪色：日常片段几天到两周就淡，事实和承诺慢一些，名字/住处/工作/学校这类“底”不归零。久没提起又不重要的事会淡出自由回忆；对方递到嘴边的线索仍可能让它模糊想起，但只给大概，不报具体日期和原话。重复提起会重新巩固，但不会回到全记得。
- 后台每 20 分钟的生活日记作为「她那边的日子」进入记忆；后台输出的「明天」和「心里」分别进入当前生活状态和反思，不和聊天事实混在一起。
- 重置这条线会删掉 `memory.json` 和运行时缓存，其他 QQ、卡本体不动。
- 面板「角色卡模式」里可以只读查看每条线记得什么。

## 对话样例与开场

`card.json` 的 `dialogue` 可以带：

- `stageHints`：每个关系阶段该怎么说话，按人物自己的节奏，不按固定台词。
- `openingHints`：第一次接话、隔几天回来、只收到「在吗」时怎么开。
- `openings`：可选，按 `first/ping/reunion/resume/casual` 给更细的开场提示；运行时优先于 `openingHints`。
- `avoid`：可选，明确不要出现的客服句、总结句、AI 腔；运行时放在 prompt 最后提醒。
- `examples`：`examples.md`，给模型学语气和停顿；样例不是固定回复。

## 相关设定（lorebook）

`card.json` 可带一个轻量 `lorebook`，借 SillyTavern World Info 的 activation key 思路：

```json
{"name":"食堂","keys":["食堂","吃饭","馒头"],"content":"食堂三楼最便宜的窗口……","priority":5}
```

- 只有当前这句话或最近两句真的提到 key，才把这条设定插进 prompt；没提到就不占位置。
- `constant: true` 的条目每次都在；`enabled: false` 可临时停用。
- 上限 4 条 / 约 1900 字，避免设定集反客为主。
- 也可以写 Character Card V2 的 `character_book.entries`，运行时兼容。

## 后台推进

- 每 20 分钟静默推进一次，不主动发消息。
- 不设 token 上限；按“角色卡 × QQ”独立跑。
- 背景推进只改剧情、心情、事件、日记、反思等状态，不直接加好感；好感只由互动和长期不聊的衰减改变。
- 后台按“日记 / 明天 / 心里”输出；日记进独立记忆，明天进当前生活状态，心里进反思。旧格式纯日记也能兼容。
- 用户不在时，角色照常生活、成长、走自己的时间线。

## 身份分支

`card.json` 的 `identityBranches` 只描述“用户是谁”带来的关系/叙事分支，不拆好感度存档。

- 用户没有明确说身份：默认普通人线。
- 用户明确说“我是陈汉升”：锁定为陈汉升线，不能改口。
- 锁定身份不等于自动走小说剧情；只有用户的实际行为命中关键事件，才向原著节点靠。
- 好感度两条身份线共用同一个值。

## 新增一张卡

1. 复制 `cards/shenyouchu/` 为 `cards/<新id>/`。
2. 改 `card.json` 的 `id`、`name`、`version`、阈值、节奏。
3. 写 `persona.md`、`behavior.md`、`examples.md`。
4. 在 `card.json` 里补 `dialogue.stageHints` / `openingHints` / `examples`。
5. 把形象图放进 `assets/`，语音素材放进 `voice/`。
6. 跑：

```bash
npm run validate
```

校验通过后提交。后台导入时按 `card.json` 建独立存档，不会覆盖已有的同名卡。

## 边界

- 不把用户私聊内容、QQ 号、记忆写进这个仓库。
- 角色卡素材可以进仓库；运行时生成的照片/语音缓存不进。
- 角色卡是个人角色设定；公开是为了让接手的人直接配置，角色素材/设定转载或商用先问。
